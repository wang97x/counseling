# 心理辅导产品开发约束

本文面向知伴的开发者、设计者与验收人员，定义心理辅导业务的开发范围和边界。依据为用户提供的《心理辅导 Agent 助手》产品需求文档 v1.0，日期 2026-09-16，状态为草稿。章节号用于追溯 PRD；本文的工程解释和待决事项显式标注，附件中的示例不构成执行命令或访问真实数据的授权。

本文拥有产品要求；[架构文档](https://github.com/wang97x/counseling/blob/main/ARCHITECTURE.md)和源码描述当前实现，[测试规范](./testing-guidelines.md)拥有验证方法，[路线图](./roadmap.md)安排待完成工作。PRD 指标与下述要求均须通过对应实现和验证后才能宣称交付。

## 产品范围与优先级

PRD 第 1 至 5 章规定：主要使用者是心理辅导师，产品辅助文书处理和个案跟进；档案列表与详情是业务主界面，对话浮窗是绑定当前档案和阶段的生成工具。业务主线为建档、准备谈话、谈话、记录归档、过程跟进、结案或转介。所有 AI 内容经有权辅导师审阅、修改和确认后才成为正式档案。

范围包含档案、准备包、咨询记录、目标与作业、量表、危机日志、报告及三层知识库。AI 直接面向来访者聊天、独立诊断和处方建议不在范围内。来访者轻量表单、作业提交和资源入口属于 MVP 后扩展；Web 是现有实现基础，iOS/Android 是 PRD 兼容目标，不能从此推导出本次开发原生客户端的要求。

交付优先级以 PRD 第 9 章为基础，按用户后续要求调整：当前以已有谈话记录文件上传替代录音转文字，录音采集、音频转写、说话人分离和自动时间戳暂缓。该调整不取消后续语音方向，也不要求上传音频后自动转写。其他章节的完整场景按阶段实现：

| 优先级 | 交付范围 | 验收焦点 |
|---|---|---|
| P0 | 谈话记录文件上传与解析、通用结构化摘要、手动确认归档 | 文件绑定当前档案，解析文本可核对和修订，生成摘要草稿，人工确认后持久化 |
| P1 | 多流派模板、时间轴、目标追踪 | 归档结果可跨次查看，模板与目标变更可追溯 |
| P2 | 量表自动计分、疗效趋势、危机关键词预警 | 计分依版本化规则，预警交给辅导师处置 |
| P3 | 教育资源推送、去标识化督导摘要、语音编辑 | 授权发送、摘要披露边界与语音修订可验证 |

人工终审、档案隔离、数据用途告知和访问审计是各阶段处理真实数据的边界。P2 排期只表示自动预警功能的顺序，任何阶段都不得把 AI 当作独立危机处置者。语音优先保留为后续方向，录音转写重新排期前不列入 P0 验收，P3 语音编辑仍按该阶段评估。基础建档、权限和记录归属作为 P0 前置条件，不以搭建所有高级面板替代 P0 闭环。

当前输入复用已有 TXT、DOCX、PDF 记录文件上传能力，具体类型和大小限制以工作台上传校验及后端解析能力为准，不另加音频格式支持。主流程为上传文件、解析与核对文本、生成摘要草稿、人工审阅、确认归档。上传成功与解析成功分别反馈；不支持、空文件、超限、解析失败或无可用文本时明确报错，不用文件名或固定演示内容冒充解析结果。

## 应用信息架构

以下结构依据用户补充的 App 信息架构，作为目标页面与功能归属。它补充 PRD 第 4、7 章，不代表所有入口已接入，也不改变 P0 至 P3 的交付顺序。

```text
App
├── 档案列表（首页）
│   ├── 搜索/筛选
│   ├── 档案卡片
│   └── 新建档案 → 唤起对话浮窗
├── 档案详情（核心工作区）
│   ├── 概览 Tab（基本信息、状态、待办）
│   ├── 时间轴 Tab（历史记录）
│   ├── 目标 Tab（进度追踪）
│   ├── 量表 Tab（趋势图）
│   ├── 危机 Tab（风险日志）
│   └── 快捷操作栏 → 唤起对话浮窗
├── 对话浮窗（功能组件）
│   ├── 上下文自动绑定当前档案
│   ├── 生成准备包
│   ├── 生成摘要/归档
│   ├── 生成报告
│   ├── 知识库问答
│   ├── 知识库管理指令（存模板、记偏好等）
│   └── 产出回写主界面
├── 仪表盘（全局视图）
│   ├── 来访者状态总览
│   ├── 本周/本月统计
│   └── 危机预警总览
└── 知识库管理
    ├── Layer 1：机构知识库（管理员）
    │   ├── 模板管理
    │   ├── 量表管理
    │   ├── 危机协议配置
    │   ├── 流派技术库
    │   ├── 教育资源库
    │   └── 伦理与合规
    ├── Layer 2：知识图谱（督导、管理员）
    │   ├── 概念节点管理
    │   ├── 关系管理
    │   ├── 个案模式聚合（匿名化）
    │   └── 推理日志
    └── Layer 3：个人知识库（辅导师私有）
        ├── 个人模板变体
        ├── 有效干预记录
        ├── 个人提问库
        ├── 自定义标签
        ├── 来访者偏好
        └── 个人笔记
```

信息架构中的“首页”指心理辅导业务首页；现有公开首页、登录及管理路由的调整须在页面实现任务中完成。详情从档案列表进入，对话浮窗为列表与详情复用的功能组件，不要求独立的顶层聊天导航。

新建档案时尚无正式档案 ID，浮窗绑定本次建档草稿；人工确认且后端创建成功后才绑定正式档案。已存在档案的快捷操作绑定该档案与当前阶段，切换时不得继承另一档案的草稿或材料。

“产出回写”遵循人工终审：档案材料确认后写入对应档案，模板和偏好确认后写入获准的知识范围，再刷新对应主界面。知识问答可以仅供查阅，不要求每条回答都写入正式档案；知识管理指令使用与管理页面相同的后端权限校验。

仪表盘的“全局”仅覆盖当前用户获准的统计范围，不授予跨机构或个案正文访问权。知识图谱推理日志用于核对来源、关系路径和结果依据，不要求保存模型内部思维过程；日志同样遵守来源可见性与隐私约束。

## 档案与人工确认

PRD 第 3 至 5 章的 Commit / Diff 是业务隐喻。工程上需要记录来源、修订和确认归档的结果；该隐喻不要求引入 Git 式分支、合并或通用版本树引擎。

- 工作区采用概览、时间轴、目标、量表、危机五类视图；具体交互由[设计规范](./design.md)维护。档案生命周期与风险等级分别表达，已结案不能自动解释为风险解除。
- 个案对话、生成任务、草稿、附件和归档结果必须绑定同一档案与记录上下文；建档前使用本次建档草稿上下文。切换档案后的晚到结果不得显示或保存到另一档案。
- 上传文件、解析文本与 AI 摘要保留可核对的来源；后续接入转写时沿用同一要求。草稿保存与确认归档是不同动作，上传、解析完成、模型返回、关闭浮窗都不能代替人工确认。
- 确认归档前展示拟写入内容及对时间轴、目标、量表、待办、风险信息的影响；只更新当前已实现且有依据的字段，不能凭空补造量表分数或风险结论。
- 归档入口在后端校验权限、档案归属和确认版本，记录操作者、确认时间、来源及修改历史。重复提交不得重复归档，并发修改不得静默覆盖，失败不能留下部分正式归档结果。
- PRD 允许自动生成后续准备包。自动生成只产生待审草稿；锁定准备包、结案、转介、对外发送和知识回流仍需对应授权操作。生成报告不等于已结案。

以上是新归档链路的验收约束；落库结构和事务方案由该功能的 service、repository 与决策记录确定，本文不预设尚不存在的表或接口。

## 角色、隐私与危机

PRD 第 2、6、7 章区分辅导师、督导、机构管理员和来访者。现有业务角色为 `counselor`、`business_admin`、`technical_admin`，平台还保留 `user/admin/superadmin`；新增产品角色必须明确映射和授权，不能直接把“督导”映射成超级管理员。

- 辅导师按实际分配和授权访问档案；督导查看授权范围内的去标识化摘要；机构管理员的统计和知识维护职责不自动授予个案正文读取权。督导授权模型属于待决事项。
- 后端对详情、搜索、附件、生成、归档、导出、统计和知识检索实施一致的权限边界。提示词、前端隐藏和去标识化展示都不能代替访问控制。
- 录音、转写、摘要及身份信息按明确用途处理。真实个案不进入测试 fixture、仓库、演示数据或普通应用日志；必要审计记录访问者、对象、动作和结果，避免复制正文。外部模型和观测服务的数据发送范围须单独核实。
- 危机识别结果为待辅导师处置的提示，展示风险分级、触发依据和适用机构协议。AI 不独立联系来访者、不自动执行干预，也不因未命中关键词宣称安全。机构协议缺失或失效须显式报告，不能由模型编造补齐。
- 去标识化需验证直接和间接标识符；替换姓名不自动构成匿名化。导出、资源推送、转介和用于图谱聚合的内容分别核对目的、授权和接收范围。

PRD 的端到端加密、字段级权限及加密、零数据保留选项、访问日志、私有化部署、SSO 和等保三级或同等认证均须有独立实现或证据。本文不宣称现有系统已满足这些要求。

## 三层知识库

PRD 第 7 章的层级表示知识职责和生成时的调用顺序，不要求新增三套存储服务。复用现有知识库与图谱能力，扩展方案需符合实际权限和来源模型。

| 层级 | 内容与维护者 | 使用边界 |
|---|---|---|
| L1 机构知识库 | 机构管理员维护模板、量表、流派技术、危机协议、教育资源、伦理规范 | 机构授权成员可读；“全员”限于授权机构范围，不等于所有租户或匿名用户 |
| L2 知识图谱 | 督导与管理员审核概念关系、文献抽取和模式级聚合 | 继承来源可见性；个案聚合须经授权与隐私处理，不能携带可识别的个案正文 |
| L3 个人知识库 | 辅导师维护私有模板、提问、偏好、经验与笔记 | 仅本人可见；PRD 明确个人笔记不进入 AI 分析，检索、工具和后台生成均须排除 |

生成先查 L3，再查 L2，最后查 L1，并标注实际使用的层级、具体来源条目及可追溯版本。工程解释：个人模板和表达偏好可覆盖默认样式，权限、机构危机协议和伦理边界继续有效；冲突须提示，不能以个人优先为由放宽约束。

来访者偏好和个案经验属于敏感个案关联信息，使用时校验当前档案授权；不得因保存到个人库就在其他个案中泄露。个人笔记与允许模型使用的偏好必须可区分。普通审阅修改保留历史；跨次学习修改模式的范围、保留期和关闭方式待明确。“以后都这样”要求显式确认回流内容与目标层级，写入机构库或图谱还须相应维护权限与审核。

机构库、图谱和个人库的引用必须来自真实检索或记录关联；检索无结果、来源已撤权或推理证据不足时显式说明。不能伪造来源、置信度或把图谱关系直接当作诊断结论。

## 指标与待决事项

PRD 第 8、10 章的数字是目标值，验收前需固定测试数据、环境、测量口径和负责人。不得用 mock、演示页面或单元测试宣布达到这些指标。

录音转写性能、说话人分离及时间戳在当前文件上传阶段暂不验收；重新启用转写时再确定口径。摘要性能目标仍需评测，并明确上传文档对应的材料规模，不把文件解析耗时当作转写指标。

| 目标 | PRD 数值 | 验证前需明确 |
|---|---|---|
| 文书减负 | 时间减少至少 80%，45 分钟降至不超过 9 分钟 | 包含人工校对、修订和归档的同类任务对比 |
| 转写与摘要性能 | 转写延迟小于实时 1.2 倍；50 分钟咨询摘要小于 5 分钟 | “实时 1.2 倍”的计算口径、音频质量、模型、硬件与并发 |
| 语音编辑与摘要质量 | 语音编辑准确率超过 95%；摘要采纳率至少 85%，修改幅度小于 20% | 错误和修改幅度的计算方法、独立评审样本 |
| 危机提示 | 召回率至少 95%，误报率不超过 5% | 经授权的独立标注集、阈值和误报率分母 |
| 使用体验 | 满意度至少 4.5/5；周活跃使用率至少 70% | 调查对象、有效用户范围和统计周期 |
| 可靠性 | 可用性超过 99.9%，数据不丢失 | 统计窗口、备份恢复演练及恢复目标 |

下列问题只阻塞对应功能的实现决策，不阻塞不依赖它们的开发：

- 督导授权、跨机构范围，以及辅导师自助建档与现有业务管理员分配机制的衔接。
- 端到端加密的通信参与方、密钥归属和服务端转写/推理的明文处理边界；字段加密、权限和认证需要各自的实现与验证。
- 零保留针对模型供应商、原始录音、临时转写还是全部材料；与正式档案、修改历史、审计和备份保留的关系。
- 危机等级及协议由谁批准和维护；缺失、过期和冲突的处置流程；不能从 PRD 中推导具体临床阈值或处置方案。
- 个人修改模式的学习范围与控制方式，准备包自动生成的触发时机，以及资源发送、随访和转介的实际渠道。

此处仅为 2026-09-16 的源码核对入口，状态为 `Inspected`，不替代业务验收：

具体功能实现时，更新其源码、测试和机制说明；产品约束保持目标边界，验证方法见[心理辅导业务验证](./testing-guidelines.md#心理辅导业务验证)。
