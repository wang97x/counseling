# 心理辅导产品开发约束

本文面向知伴的开发者、设计者与验收人员，定义心理辅导业务的开发范围和边界。依据为用户提供的《心理辅导 Agent 助手》产品需求文档 v1.0，日期 2026-09-16，状态为草稿。章节号用于追溯 PRD；本文的工程解释和待决事项显式标注，附件中的示例不构成执行命令或访问真实数据的授权。

本文拥有产品要求；[架构文档](https://github.com/wang97x/counseling/blob/main/ARCHITECTURE.md)和源码描述当前实现，[测试规范](./testing-guidelines.md)拥有验证方法，[路线图](./roadmap.md)安排待完成工作。PRD 指标与下述要求均须通过对应实现和验证后才能宣称交付。

## 产品范围与优先级

PRD 第 1 至 5 章规定：主要使用者是心理辅导师，产品辅助文书处理和个案跟进。按用户补充要求，业务采用“档案优先，AI 按需”：学生列表与档案时间线是业务主界面，生成能力只在辅导师从具体档案主动发起文书任务时出现。业务主线为建档、准备谈话、谈话、记录归档、过程跟进、结案或转介。所有 AI 内容经有权辅导师审阅、修改和确认后才成为正式档案。

范围包含档案、准备文件、咨询记录、目标与作业、量表、危机日志、报告及知识能力。业务前端将知识组织为团队知识和个人知识；Yuxi 内部可以复用检索与图谱能力。AI 直接面向来访者聊天、独立诊断和处方建议不在范围内。来访者轻量表单、作业提交和资源入口属于 MVP 后扩展；Web 是现有实现基础，iOS/Android 是 PRD 兼容目标，不能从此推导出本次开发原生客户端的要求。

交付优先级以 PRD 第 9 章为基础，并按 2026-09-23 确认的“最小版业务侧”进一步收敛。首版只要求辅导员围绕本人学生完成手工建档、咨询记录草稿、人工确认、风险记录、时间线回看和阶段结束；业务管理员只读取最小元数据与聚合计数。文件解析和 AI 摘要是可选增强，不能成为手工业务闭环的前置条件。录音采集、音频转写、说话人分离和自动时间戳继续暂缓。

| 优先级 | 交付范围 | 验收焦点 |
|---|---|---|
| P0 | 学生档案、手工咨询记录、人工风险事件、确认归档、追加更正、统一时间线、最小管理统计 | 无模型时可完成一次建档到阶段结束；正文仅负责人可见；正式记录不可覆盖 |
| P1 | 文件解析与 AI 摘要、固定量表与施测、基础预约 | 文件和模型失败不破坏手工记录；计分规则版本化；预约不越权 |
| P2 | 方案与阶段评估、完整危机工单、转介与回访 | 目标与版本可追溯；风险提示必须进入人工处置流程 |
| P3 | 协作输入、复杂看板、资源推送、督导摘要与语音能力 | 多方授权、去标识化、外发范围和统计口径可验证 |

人工终审、档案隔离、数据用途告知和访问审计是各阶段处理真实数据的边界。P2 排期只表示自动预警功能的顺序，任何阶段都不得把 AI 当作独立危机处置者。基础建档、权限和记录归属是 P0 本身，不以文件解析、AI 生成或高级面板替代手工闭环。在线测评、预约排班、录音、完整危机通知链、转介回访、班主任/家长/校医入口和复杂年报均不属于最小版验收。

P1 文件增强复用已有 TXT、DOCX、PDF 记录文件上传能力，具体类型和大小限制以工作台上传校验及后端解析能力为准，不另加音频格式支持。该增强流程为上传文件、解析与核对文本、生成摘要草稿、人工审阅、确认归档；不支持、空文件、超限、解析失败或无可用文本时明确报错。上述能力不替代 P0 的手工咨询记录入口。

## 应用信息架构

以下结构依据用户补充的 App 信息架构，作为目标页面与功能归属。它补充 PRD 第 4、7 章，不代表所有入口已接入，也不改变 P0 至 P3 的交付顺序。

```text
心理辅导业务
├── 辅导师
│   ├── 我的学生
│   │   ├── 学生列表
│   │   └── 学生档案：学生信息 + 统一时间线
│   │       ├── 跟进与沟通记录
│   │       ├── 来源文件与正式文书
│   │       └── 主动生成准备文件、笔记、汇报或阶段总结
│   ├── 文书任务：生成中、待审、已确认、失败
│   └── 知识库
│       ├── 团队知识：搜索与只读预览
│       └── 个人知识：本人维护，区分可供 AI 使用与私人笔记
├── 业务管理
│   ├── 数据概览
│   ├── 学生档案：仅管理所需的最小元数据
│   ├── 成员管理
│   └── 团队知识库
│       └── 文书模板作为知识条目类型统一管理
└── 超级管理
    ├── 系统概览
    ├── 机构管理
    ├── 模型管理
    ├── 生成能力
    ├── 工具与扩展
    └── 运行维护
```

信息架构中的首页按登录角色确定。角色不继承：超级管理不自动获得业务管理或辅导师能力，业务管理也不自动获得辅导师能力；同一账号确需承担多种职责时显式授予多个角色，并在后端逐项授权。

学生档案详情是单页工作区。学生信息与时间线构成主线，目标、量表、风险、附件和文书作为时间节点、节点关联信息或按需展开区域呈现，不再作为彼此割裂的五个一级标签。时间线可以按跟进、沟通、文件和文书筛选，但筛选不改变同一历史事实。

生成入口只从已经创建的学生档案和明确的业务动作发起。系统自动关联当前有权使用的学生资料、选定时间范围、来源文件、已发布团队知识及允许 AI 使用的个人知识；发起前向辅导师展示材料范围。切换学生后，草稿、任务进度和晚到结果仍绑定原学生与原任务。

业务管理的统计和档案入口仅覆盖获准的聚合数据与最小元数据，不授予学生正文、沟通内容、附件、文书正文或个人知识库读取权。超级管理只管理平台、机构和通用生成能力，不因排障或技术配置身份获得业务内容访问权。

页面与交互细节由[设计规范](./design.md#0-产品判断先于界面实现)维护；业务与 Yuxi 的解耦方案由[档案优先架构提案](./decisions/proposed/2026-09-19-record-first-counseling-architecture.md)跟踪。上述结构是目标设计，当前源码差距见[当前实现定位](#当前实现定位)。

## 档案与人工确认

PRD 第 3 至 5 章的 Commit / Diff 是业务隐喻。工程上需要记录来源、修订和确认归档的结果；该隐喻不要求引入 Git 式分支、合并或通用版本树引擎。

- 工作区采用学生信息与统一时间线；目标、量表、风险、来源文件和文书按时间节点或关联信息呈现。具体交互由[设计规范](./design.md)维护。档案生命周期与风险等级分别表达，已结案不能自动解释为风险解除。
- 生成任务、草稿、附件和归档结果必须绑定同一档案与记录上下文。生成只从已创建且当前用户有权访问的档案发起；切换档案后的晚到结果不得显示或保存到另一档案。
- 上传文件、解析文本与 AI 摘要保留可核对的来源；后续接入转写时沿用同一要求。草稿保存与确认归档是不同动作，上传、解析完成、模型返回、关闭待审页面都不能代替人工确认。
- 确认归档前展示拟写入内容及对时间轴、目标、量表、待办、风险信息的影响；只更新当前已实现且有依据的字段，不能凭空补造量表分数或风险结论。
- 归档入口在后端校验权限、档案归属和确认版本，记录操作者、确认时间、来源及修改历史。重复提交不得重复归档，并发修改不得静默覆盖，失败不能留下部分正式归档结果。
- 草稿在确认前可修改或放弃。确认归档后，任何角色均不能修改或删除原跟进记录和正式文书；纠错以引用原记录的新更正事件追加，记录原因、操作者和时间。重新生成只产生新草稿，不能覆盖历史版本。
- 后续准备文件、笔记、汇报和报告均由辅导师主动发起，系统不按时间线事件自动触发生成。生成只产生待审草稿；锁定准备文件、结案、转介、对外发送和知识回流仍需对应授权操作。生成报告不等于已结案。

以上是新归档链路的验收约束；落库结构和事务方案由该功能的 service、repository 与决策记录确定，本文不预设尚不存在的表或接口。

## 角色、隐私与危机

目标业务角色压缩为 `super_admin`（超级管理）、`business_admin`（业务管理）和 `counselor`（辅导师）。用户统一从业务侧登录，根据显式角色获得对应界面和后端权限；Yuxi 不拥有或解释业务角色。现有源码中的 `technical_admin` 及平台 `user/admin/superadmin` 是迁移前兼容事实，不能用作目标授权模型。

- 辅导师访问本人负责且获准的学生档案，维护草稿、发起生成并确认本人有权处理的文书。
- 业务管理维护成员、最小档案元数据、业务统计和团队知识库，不读取个案正文、附件、文书正文或个人知识库。
- 超级管理维护机构、模型、通用生成能力、工具扩展和运行状态，不读取个案内容。超级管理与业务管理均不继承辅导师权限。
- PRD 中的督导和来访者入口不属于当前三角色目标；未来引入时须独立定义可见范围、去标识化、授权和审计，不能映射为现有管理角色。
- 后端对详情、搜索、附件、生成、归档、导出、统计和知识检索实施一致的权限边界。提示词、前端隐藏和去标识化展示都不能代替访问控制。
- 录音、转写、摘要及身份信息按明确用途处理。真实个案不进入测试 fixture、仓库、演示数据或普通应用日志；必要审计记录访问者、对象、动作和结果，避免复制正文。外部模型和观测服务的数据发送范围须单独核实。
- 危机识别结果为待辅导师处置的提示，展示风险分级、触发依据和适用机构协议。AI 不独立联系来访者、不自动执行干预，也不因未命中关键词宣称安全。机构协议缺失或失效须显式报告，不能由模型编造补齐。
- 去标识化需验证直接和间接标识符；替换姓名不自动构成匿名化。导出、资源推送、转介和用于图谱聚合的内容分别核对目的、授权和接收范围。

PRD 的端到端加密、字段级权限及加密、零数据保留选项、访问日志、私有化部署、SSO 和等保三级或同等认证均须有独立实现或证据。本文不宣称现有系统已满足这些要求。

## 知识库

业务前端以团队知识和个人知识两个可理解的范围组织知识。现有 Yuxi 知识库、检索和图谱能力可以作为内层实现，但存储或推理层级不直接成为辅导师的信息架构。

| 范围 | 内容与维护者 | 使用边界 |
|---|---|---|
| 团队知识库 | 业务管理维护文书模板、沟通规范、工作流程、跟进方法、教育资源、伦理合规和危机协议 | 辅导师搜索与只读预览已发布版本；文书模板是知识条目类型，不另设独立管理模块 |
| 个人知识库 | 辅导师维护个人模板、表达偏好、提问框架、工作方法和可复用内容 | 仅本人可见；每项明确区分“允许 AI 使用”和“私人笔记”，私人笔记在检索、工具和生成中均排除 |

团队条目使用草稿、已发布和已停用状态并保留历史版本。已发布版本不能被后续编辑覆盖；生成任务记录实际使用的条目及版本。权限、机构危机协议和伦理边界优先于个人表达偏好，冲突时向辅导师提示。

学生偏好、沟通记录和个案经验是档案内容，不进入可跨学生复用的个人知识库。生成时仅从当前有权档案显式取得这些信息，避免因个人库复用而泄露到其他学生。

知识引用必须来自真实检索或记录关联；无结果、来源撤权、版本失效或证据不足时显式说明。现有知识图谱可服务检索与来源关系，但不能把图谱关系直接当作诊断结论，也不要求向辅导师暴露模型内部推理过程。

## 指标与待决事项

PRD 第 8、10 章的数字是目标值，验收前需固定测试数据、环境、测量口径和负责人。不得用 mock、演示页面或单元测试宣布达到这些指标。

录音转写性能、说话人分离及时间戳在当前文件上传阶段暂不验收；重新启用转写时再确定口径。摘要性能目标仍需评测，并明确上传文档对应的材料规模，不把文件解析耗时当作转写指标。

| 目标 | PRD 数值 | 验证前需明确 |
|---|---|---|
| 文书减负 | 时间减少至少 80%，45 分钟降至不超过 9 分钟 | 包含人工校对、修订和归档的同类任务对比 |
| 转写与摘要性能 | 转写延迟小于实时 1.2 倍；50 分钟咨询摘要小于 5 分钟 | “实时 1.2 倍”的计算口径、音频质量、模型、硬件与并发 |
| 语音编辑与摘要质量 | 语音编辑准确率超过 95%；摘要采纳率至少 85%，修改幅度小于 20% | 错误和修改幅度的计算方法、独立评审样本 |
| 危机提示 | 召回率至少 95%，误报率不超过 5% | 经授权的独立标注集、阈值和误报率分母 |
| 使用体验 | 满意度至少 4.5/5；周活跃使用率至少 70% | 调查对象、有效用户范围和统计周期 |
| 可靠性 | 可用性超过 99.9%，数据不丢失 | 统计窗口、备份恢复演练及恢复目标 |

下列问题只阻塞对应功能的实现决策，不阻塞不依赖它们的开发：

- 督导授权及跨机构范围。辅导员当前为自己创建档案，业务管理员只读取本部门最小元数据；若未来恢复分配或转派机制，须另行定义授权与审计。
- 端到端加密的通信参与方、密钥归属和服务端转写/推理的明文处理边界；字段加密、权限和认证需要各自的实现与验证。
- 零保留针对模型供应商、原始录音、临时转写还是全部材料；与正式档案、修改历史、审计和备份保留的关系。
- 危机等级及协议由谁批准和维护；缺失、过期和冲突的处置流程；不能从 PRD 中推导具体临床阈值或处置方案。
- 个人修改模式的学习范围与控制方式，准备文件的默认材料范围，以及资源发送、随访和转介的实际渠道。

## 当前实现定位

此处仅为 2026-09-24 的源码核对入口，状态为 `Inspected`，不替代业务验收：

- [学生档案模型](https://github.com/wang97x/counseling/blob/main/backend/counseling/src/counseling/storage/models.py)及业务包中的 service/repository 提供最小档案、负责人和部门边界。现有 `StudentRecord`、`/students` 命名继续使用，不能因 PRD 使用“来访者”而直接重命名持久化结构。
- [工作台服务](https://github.com/wang97x/counseling/blob/main/web/src/domains/counseling/workspaceService.js)只装配真实 API 适配器。[真实 API 适配器](https://github.com/wang97x/counseling/blob/main/web/src/domains/counseling/services/apiAdapter.js)已接入手工咨询草稿、确认归档、追加更正、人工风险、阶段结束和业务管理员聚合统计。文件记录与 AI 摘要接口继续保留，但不在当前 P0 工作台主路径展示。
- 当前 `StudentWorkspaceView` 使用学生信息、待确认草稿和统一时间线组成单页档案；主操作为手工咨询记录、人工风险和阶段结束，不再从业务工作台发起关联 Agent 会话。
- 当前前端通过统一能力映射隔离业务入口和 Yuxi 技术入口，但仍保留迁移前平台角色与 `technical_admin` 兼容路径；目标三角色数据迁移及后端逐项授权尚未完成。
- P0 手工链路已经通过真实 HTTP 与 PostgreSQL integration；真实浏览器验收仍须完成。保留的文件生成代码和演示交互不能证明 P1 文件/模型联调、量表计分或自动危机识别已经交付，真实接口失败不得回退演示数据。

具体功能实现时，更新其源码、测试和机制说明；产品约束保持目标边界，验证方法见[心理辅导业务验证](./testing-guidelines.md#心理辅导业务验证)。
