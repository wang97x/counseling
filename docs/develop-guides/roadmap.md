# 开发路线图

## 知伴二次开发方向

心理辅导业务以 PRD v1.0（2026-09-16，草稿）、[产品约束](./counseling-product-contract.md)及[档案优先架构提案](./decisions/proposed/2026-09-19-record-first-counseling-architecture.md)为范围依据。当前已有最小学生档案、会话关联和五标签工作区入口；真实 API 适配器尚未接入摘要生成和正式归档。页面原型和演示流程不构成 P0 交付。

后续先建立业务边界，再按 PRD 能力顺序推进：

1. 业务边界：统一业务登录，收敛 `super_admin`、`business_admin`、`counselor` 三类显式角色；建立独立的学生、跟进、沟通、文书和审计领域，并以生成端口隔离 Yuxi。此阶段不要求一次性移动全部现有目录。
2. 档案主线：把五标签和通用 Conversation 入口收敛为学生信息与统一时间线，完成草稿、确认归档、历史不可变和追加更正的持久化闭环。
3. P0 文件生成：从学生档案上传已有谈话记录文件，完成解析与核对；结合选定档案信息、已发布团队知识和允许 AI 使用的个人知识，通过 Yuxi 生成待审文书，再复制到业务存储并由辅导师确认。真实模型与文件解析联调属于本阶段验收。
4. 知识与管理：提供辅导师团队知识只读预览和个人知识维护；业务管理统一维护版本化团队知识与文书模板；超级管理承接机构、模型、通用生成能力和运行维护。
5. P1：多流派模板、跨次时间线、目标与作业追踪。
6. P2：量表计分、疗效趋势和危机关键词预警，建立独立评测及人工处置流程。
7. P3：教育资源推送、去标识化督导摘要和语音编辑。督导角色若进入实现，另行定义授权，不并入现有管理角色。

录音采集、音频转写、说话人分离和自动时间戳暂缓，重新排期前不作为 P0 的完成条件；当前复用已有记录文件上传入口。

准备文件、结案/转介、业务统计和知识协同按上述阶段的实际依赖拆分，不据此扩大每次任务。督导授权、档案转派、加密、保留策略等[待决事项](./counseling-product-contract.md#指标与待决事项)在对应功能实施前明确。[早期最小业务版提案](./decisions/proposed/2026-09-12-counseling-minimal-release.md)保留背景，其无模型优先的排期不再决定 PRD 的交付顺序。

这里记录尚未完成的方向，不代表已经实现或一定会在某个版本发布。需求和优先级会根据 Issue、讨论和维护资源调整；欢迎在 [GitHub Issues](https://github.com/wang97x/counseling/issues) 提交建议。

## 计划中的不兼容方向

以下 Yuxi 平台方向为独立候选，不自动进入心理辅导 MVP；需有当前业务需求及独立决策才安排实现。

后续 0.8 版本可能包含：

- 升级 Milvus 3.0；
- 进一步解除 API/worker 对共享文件系统的依赖，支持更清晰的分布式部署边界。

这两项会影响部署和数据迁移，确定方案前会单独说明升级条件和兼容范围。

## 知识库

- 为知识导图增加基于文件名的关联边，并探索用聚类形成社区节点。
- 增加按关键词排序的 `query_keywords` 工具。
- 丰富检索结果中的 metadata 和标签。
- 为个人工作区增加检索能力，但不做向量化。

## 智能体

- 为子智能体增加 Steer 机制。
- 增加子智能体向主智能体提问的 `ask_for_main_agent` 能力。
- 设计子智能体之间的通信机制。

## 其他

- 继续完善基于 DeepAgents 文件后端的 Memory 方案，并明确它与现有用户级 Memory 的边界。
- 改进 `ask_user_question`：支持较长文本回答，并让流式输出期间的聊天区域保持跟随最新内容。

## 已知问题

- 打开历史对话时自动滚动到消息末尾。
