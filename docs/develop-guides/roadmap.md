# 开发路线图

## 知伴二次开发方向

心理辅导业务以 PRD v1.0（2026-09-16，草稿）、[产品约束](./counseling-product-contract.md)及[最小业务后端决策](./decisions/implemented/2026-09-23-minimal-counseling-backend.md)为范围依据。2026-09-23 起，首版不再以八个并列模块或 AI 文件生成为交付前提，而以“建档—手工咨询记录—人工风险—确认归档—时间线—阶段结束”作为唯一 P0 闭环。

后续先建立业务边界，再按 PRD 能力顺序推进：

1. P0 后端：学生最小资料与负责人隔离；手工咨询草稿、版本修订、人工确认、不可变正式记录、追加更正；人工风险事件与当前投影；负责人时间线和业务管理员最小统计。
2. P0 前端：把五标签收敛为学生信息与统一时间线，接入手工记录、风险记录、阶段结束和刷新后回读，不以演示数据或 AI 返回代替正式档案。
3. P0 验证：真实 PostgreSQL、HTTP 和权限负控；正式记录/更正触发器；旧版本、重复确认、跨辅导员和管理员正文访问均失败。
4. P1：完成文件解析与 AI 摘要的真实 MinIO/模型联调，并另行建设固定量表与基础预约；三者都不能扩大 P0 权限。
5. P2/P3：方案评估、危机工单、转介回访、协作输入和复杂看板按出现的真实业务依赖分别决策，不预建通用工作流。

录音采集、音频转写、说话人分离和自动时间戳暂缓；现有记录文件上传入口作为 P1 增强继续演进，不作为 P0 完成条件。

准备文件、结案/转介、业务统计和知识协同按上述阶段的实际依赖拆分，不据此扩大每次任务。督导授权、档案转派、加密、保留策略等[待决事项](./counseling-product-contract.md#指标与待决事项)在对应功能实施前明确。[早期最小业务版提案](./decisions/proposed/2026-09-12-counseling-minimal-release.md)保留背景，其无模型优先的排期不再决定 PRD 的交付顺序。

这里记录尚未完成的方向，不代表已经实现或一定会在某个版本发布。需求和优先级会根据 Issue、讨论和维护资源调整；欢迎在 [GitHub Issues](https://github.com/wang97x/counseling/issues) 提交建议。

## 计划中的不兼容方向

以下 Yuxi 平台方向为独立候选，不自动进入心理辅导 MVP；需有当前业务需求及独立决策才安排实现。

后续 0.8 版本可能包含：

- 升级 Milvus 3.0；
- 进一步解除 API/worker 对共享文件系统的依赖，支持更清晰的分布式部署边界。

这两项会影响部署和数据迁移，确定方案前会单独说明升级条件和兼容范围。

## 知识库

- 为知识导图增加基于文件名的关联边，并探索用聚类形成社区节点。
- 增加按关键词排序的 `query_keywords` 工具。
- 丰富检索结果中的 metadata 和标签。
- 为个人工作区增加检索能力，但不做向量化。

## 智能体

- 为子智能体增加 Steer 机制。
- 增加子智能体向主智能体提问的 `ask_for_main_agent` 能力。
- 设计子智能体之间的通信机制。

## 其他

- 继续完善基于 DeepAgents 文件后端的 Memory 方案，并明确它与现有用户级 Memory 的边界。
- 改进 `ask_user_question`：支持较长文本回答，并让流式输出期间的聊天区域保持跟随最新内容。

## 已知问题

- 打开历史对话时自动滚动到消息末尾。
