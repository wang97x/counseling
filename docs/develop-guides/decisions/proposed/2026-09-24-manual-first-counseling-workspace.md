# 手工优先的心理辅导工作台

状态：proposed
类型：feature
Owner：web/src/domains/counseling/views/StudentWorkspaceView.vue

## 问题

最小业务后端已经支持手工咨询草稿、人工确认、追加更正、人工风险事件、统一时间线、阶段结束和业务管理员聚合统计，但当前生产工作台仍以文件上传、AI 摘要和关联 Agent 会话作为主要动作。辅导员无法仅通过业务页面完成从建档到阶段结束的 P0 闭环，页面中的五个标签还会把未接入的目标、量表和危机能力表现为当前工作区的一部分。

## 提案

- 学生详情改为学生信息、待确认草稿和统一时间线组成的单页工作区，不再显示目标、量表和危机等未接入标签。
- 主操作只保留新增手工咨询记录、记录人工风险和阶段结束。文件上传、AI 摘要和关联 Agent 会话不再出现在生产工作台主路径；其后端能力继续保留，后续有独立验收时再提供按需入口。
- 手工咨询记录先持久化为可恢复草稿，辅导员可继续修订，再以独立动作人工确认归档。正式记录不能编辑，纠错通过时间线节点上的追加更正完成。
- 风险只允许辅导员手工记录，并展示服务端当前风险投影和历史事件；页面不根据咨询正文自动推断风险。
- 阶段结束使用专用接口、乐观版本和必填结束说明，不再通过普通档案编辑提交 `closed`。
- 业务管理员在档案列表页读取最小聚合统计，不增加正文访问入口。

## 替代方案

- 保留文件上传和 Agent 会话为首要按钮，同时新增手工记录：会继续让增强能力与基本业务闭环争夺主路径，因此不采用。
- 在一个表单中直接创建正式记录：交互更短，但会消除草稿与人工确认边界，因此不采用。
- 为手工记录、风险和阶段结束继续保留独立标签：入口清楚，但与统一时间线的产品主线冲突，因此使用上下文动作和时间线节点。

## 验收标准

| 验收主张 | 失败面 | 语义 Owner | 直接证据 / 命令 | 负向案例 | 当前结果 |
|---|---|---|---|---|---|
| 辅导员可从页面创建、恢复、修订并确认手工记录 | 页面仍只能上传文件或一次提交直接归档 | counseling API adapter、学生工作台 | Web unit、build、真实 HTTP/PostgreSQL integration | 旧版本冲突不覆盖新草稿；未确认草稿不进入时间线 | Not run |
| 正式记录只能追加更正 | 页面原地修改正式正文 | 时间线映射、学生工作台 | Web unit 与既有 PostgreSQL 不可变触发器 integration | 正式节点无编辑动作，更正形成独立节点 | Not run |
| 人工风险成为当前档案事实 | 页面固定显示未知或从正文推断风险 | 学生映射、风险表单、时间线 | Web unit、真实 HTTP/PostgreSQL integration | 未评估不显示为常规；页面不包含自动判断入口 | Not run |
| 阶段结束走专用确认动作 | 普通编辑提交 `closed` 后由后端拒绝 | counseling API adapter、学生工作台 | Web unit、真实 HTTP/PostgreSQL integration | 缺少说明、旧版本和重复结束均不伪装成功 | Not run |
| 业务管理员只看到聚合与最小元数据 | 统计页泄露正文或允许打开详情 | 列表页、管理统计 API | Web unit、真实 HTTP/PostgreSQL integration | 管理员仍不能进入档案详情 | Not run |
| AI 不占用当前 P0 主路径 | 工作台仍突出上传摘要或 Agent 会话 | 学生工作台 | 源码负向断言与真实页面检查 | 主操作区出现上传、生成摘要或打开助手时测试失败 | Not run |

## 风险

- 现有文件草稿仍可能存在；本次不删除数据和接口，只从主路径移除入口，后续恢复时需要提供独立任务列表。
- 当前前端测试包含演示上传流程的历史覆盖；保留底层组件测试不代表该能力仍在生产工作台暴露。
- 本次不新增自动风险判断、量表、预约、目标、转介或危机工单，也不改变后端权限与持久化结构。
