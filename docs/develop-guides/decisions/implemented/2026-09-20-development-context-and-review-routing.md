# 按改动范围路由开发上下文与 Review

状态：implemented
类型：simplification
Owner：AGENTS.md
取代：无

## 问题

根指令曾把产品约束、架构、流程、信任、测试和贡献指南同时列为任务启动材料，子树指令又要求读取完整架构或设计规范。局部修改因此在定位源码前装载大量无关上下文。所有代码变更还使用同一种全新上下文 Review，重复读取完整规范，固定成本与改动风险不成比例。

## 决策

根 `AGENTS.md` 只保留全局安全边界、最小工作流程和路径/风险路由。Agent 默认读取根指令、改动路径最近的子树指令、真实源码 Owner 和相关测试；产品、架构、流程、测试、贡献及并行环境文档仅在路由条件成立时读取相关章节。

Review 分为豁免、轻量和完整三级。不改变行为、契约或治理语义的文案、链接或机械等价修改经自检与相关 gate 后可免 Reviewer Agent；普通单 Owner 代码修改由全新上下文 Reviewer 读取有界 review packet；权限、持久化、事务、Run/worker、文件隔离、正式归档、模型可见输入、外部副作用、公开兼容、长期治理或跨 Owner 变更执行完整 Review，并优先于其他等级。开发 SubAgent 只用于边界清楚且可独立并行的任务，不用于单文件搜索、局部编辑或单个测试。

`scripts/verify_engineering_contracts.py` 使用更小的分层 `AGENTS.md` 字符预算，并拒绝已移除的无条件加载措辞。详细测试命令、产品契约和机制事实继续由现有 owning 文档维护，历史 decision 保持按需检索。

## 替代方案

- 保持全部材料为启动必读：边界最保守，但小改动继续支付全项目上下文和重复 Review 成本。
- 删除或合并大量正式文档：文档未被加载时本身不消耗模型上下文，还会损失按需检索的专题 Owner。
- 所有代码变更取消独立 Review：成本最低，但高风险边界失去独立语义检查。
- 只依赖模型自行判断读取范围：无需规则变化，但明确的全文加载指令会覆盖这种优化，且不同 Agent 行为不稳定。

## 后果

四个分层指令合计为 5020 个字符。根、Backend、Web、Docs 指令预算分别为 2800、1100、700 和 1000 个字符。局部任务不再预先读取六份通用开发指南；Web 非界面修改也不再默认读取完整设计规范。

路由条件遗漏可能使 Agent 少读必要背景。根指令继续保留安全边界，高风险列表使用明确枚举，Reviewer 可以升级等级。后续缺陷把最小缺失规则放入对应路径或路由条件，不复制完整专题文档。

分级判断仍包含语义判断。PR 记录等级、依据、输入 packet 和未验证范围；Reviewer 发现范围跨越 Owner 或风险升高时改用完整 Review。

## 验证

- `python3 -m unittest scripts.test_verify_engineering_contracts`：Passed，64 个测试通过；负向用例证明两种已移除的全量加载规则会被拒绝，条件式按需读取保持允许。
- `python3 scripts/verify_engineering_contracts.py`：Passed，检查 4 个分层指令、链接、预算和 decision lifecycle。
- `cd docs && pnpm run build`：Passed。
- `git diff --check`：Passed；命令仅报告工作树既有 CRLF 转换提醒，没有 whitespace error。
- 负向搜索：当前根和子树指令不存在“每次任务先加载”或“先阅读根”措辞；历史 decision 中的旧流程描述不构成当前指令。
- 独立 Review：Passed；全新上下文 Reviewer 核对目标、完整相关 diff、测试与未验证范围，提出的文档加载冲突、Review 等级优先级和 verifier 误报风险均已修复，增量复核未发现新增问题。

旧能力不存在：任务启动不再无条件要求读取六份通用指南，普通单 Owner Review 不再要求读取完整规范，四个旧字符预算已由更小预算替换。

重新引入条件：若实际任务复盘证明按需路由持续遗漏跨模块安全边界，且路径 gate、测试和高风险 Review 无法阻止，可将被遗漏的最小不变量提升为根常驻规则；不恢复整份文档的无条件全文加载。
