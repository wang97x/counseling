# 心理辅导 PRD 驱动的开发约束

状态：implemented
类型：process
Owner：AGENTS.md

## 问题

现有开发约定以通用 Yuxi 平台为中心，旧业务提案以学生档案和无模型验证为先。用户提供《心理辅导 Agent 助手》PRD v1.0（2026-09-16，草稿），要求据此重构 Markdown 约束。后续开发需要统一产品方向，并区分产品要求、已接入接口和演示能力。

## 决策

[产品约束](../../counseling-product-contract.md)承接 PRD 章节、范围、P0 至 P3 优先级和待明确事项；根与子树 AGENTS 保留各自执行规则和链接。设计、测试与路线图分别拥有交互要求、验证方式和后续顺序。ARCHITECTURE 描述当前实现。[旧提案](../proposed/2026-09-12-counseling-minimal-release.md)保留背景，其无模型优先排期由产品约束接管。

本次只改文档与导航，不实现转写、归档、危机预警、加密或新角色，不修改数据库、业务代码、依赖和部署拓扑。原始 DOCX 不提交到仓库；记录标题、版本和日期以追溯来源。

用户补充的 App 信息架构由产品约束完整保存，设计规范引用同一入口。结构区分页面与对话功能组件，新建浮窗绑定建档草稿，人工确认后的写入按档案或知识内容归属落到对应范围。业务仪表盘与知识图谱推理日志不扩大数据访问权限。

用户明确将当前录音转文字替换为文件上传。P0 采用已有记录文件上传、解析、摘要和人工归档，音频转写及其指标延后；保留 PRD 中的语音方向以便后续单独排期。上传和解析必须分别验证，不能把该调整写成摘要或归档已接入。

## 替代方案

- 仅把产品名改成心理辅导：无法约束人工归档、知识来源及角色边界。
- 把完整 PRD 复制到所有 AGENTS：重复规则容易漂移，增加每次任务的阅读负担。
- 按 PRD 改写现有架构为目标实现：会把演示和未接入能力误报成已交付。

## 后果

PRD 未明确督导授权模型、端到端加密与服务端推理的边界、零保留与档案留存的关系。文档记录待决事项及实现前需明确的条件，不代替用户选择方案。个人知识优先不能授权越权读取或覆盖机构危机协议。指标属于待验证目标，不能作为医疗效果、合规认证或产品能力的完成声明。

产品规则的生效范围是后续开发与验收，不意味着现有产品已符合全部规则。文档不要求普通附件上传创建 AgentRun，也不因版本树或三层知识的产品隐喻引入通用引擎或新存储服务。
